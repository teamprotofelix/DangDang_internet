# DangDang_internet

브라우저에서 대화하고 함께 놀 수 있는 Chrome Manifest V3 반려 AI입니다. 사이드 패널과 플로팅 아바타, 로컬 대화 이력과 기억, 범용 코딩 프로젝트, KIPRIS PLUS 특허 심사품질 진단을 지원합니다.

## 로컬 설치

### 설치용 ZIP

[GitHub Actions](https://github.com/teamprotofelix/DangDang_internet/actions/workflows/ci.yml)의 성공한 실행에서 **DangDang_internet_Chrome**을 내려받아 압축을 풉니다. Chrome 122 이상에서 `chrome://extensions`를 열고 **개발자 모드 → 압축해제된 확장 프로그램을 로드합니다**를 선택한 다음 `manifest.json`이 있는 폴더를 지정합니다. 설치용 ZIP에는 PDF.js 본체, 워커, 문자 매핑 및 표준 글꼴이 포함되어 Node.js와 npm 없이 사용할 수 있습니다.

### 소스 ZIP

GitHub **Code → Download ZIP**으로 받은 소스를 사용하려면 Node.js 24에서 `npm ci`와 `npm run package:extension`을 실행하고 `dist/DangDang_internet`을 로드합니다. 확장 프로그램의 **설정**에서 제공자와 API 키를 저장한 뒤 **연결 테스트**로 확인합니다.

이미 설치한 확장에 PDF.js가 빠졌다면 설치용 ZIP을 풀고 **기존 확장 폴더의 경로를 유지하면서** 내용을 갱신한 후 Chrome에서 다시 로드합니다. **텍스트 추출 재시도**는 로컬에 저장된 PDF를 사용합니다.

## 대화와 코딩

- 대화창에서 **코드 요청**을 켜고 보냅니다. 드롭다운에서 **자동 감지**, 지원 언어 또는 **직접 입력**을 선택합니다. 이후 메시지도 같은 프로젝트 파일을 참고해 수정합니다. 코드 요청을 끄면 일반 대화로 돌아갑니다.
- **코딩** 탭의 **새 프로젝트**는 빈 상태에서 시작하고 **수정 요청**은 현재 파일을 사용합니다. **다시 생성**은 해당 요청의 입력·언어·원본 파일을 재사용합니다. 새 결과가 저장되면 현재 프로젝트가 바뀝니다. 프로젝트 파일 목록에서 선택한 소스는 복사하거나 저장할 수 있으며, 프로젝트 ZIP은 하위 폴더와 UTF-8 파일명을 보존합니다. 파일명과 확장자는 코딩 탭에서 편집할 수 있습니다.
- 모델이 반환한 소스는 텍스트로 표시합니다. 다운로드한 파일의 내용은 직접 확인한 뒤 별도 환경에서 사용하세요. 이전 HTML 세션은 `app.html`로 복원됩니다.
- **LG EXAONE (K-EXAONE 2.5)**는 `k-exaone_v2.5`를 사용합니다. 제공자마다 키가 분리되며 생성 한도에는 추론 토큰이 포함됩니다. 서비스 혼잡 시 429가 표시될 수 있습니다. [EXAONE API 문서](https://docs.exaone.ai/ko/docs/k-exaone-2.5)

## 특허 심사품질 진단

1. **설정 → KIPRIS PLUS**에 본인의 키를 저장합니다. 상품 권한이 있는 출원번호로 연결을 검사합니다.
2. **특허 진단**에 13자리 특허·실용신안 출원번호를 입력하고 **서류 조회·다운로드**를 누릅니다. 로컬에 확보한 원문은 **열기** 또는 **PDF 다운로드**로 확인합니다. 화면에 원문 검증과 추출 상태가 별도로 표시됩니다. 조회 실패는 **원문 다시 조회**, 저장된 파일의 추출 실패는 **텍스트 추출 재시도**로 복구합니다.
3. **진단 시작**을 누르면 전송할 LLM 주소와 모델이 표시됩니다. 동의 후 누락된 자료 조회를 시도하고 확보한 원문으로 검토합니다. 전송에 동의하지 않아도 조회와 다운로드를 이용할 수 있습니다.
4. 보고서는 문서별 상태, OA·RD·RC 규칙, 통지 당시 청구항 판본, 근거 쪽수와 미검토 범위를 보여줍니다. MD·TXT·JSON·PDF·HWPX로 저장할 수 있습니다. **이 출원 자료 삭제**로 로컬 기록과 원문을 지웁니다.

### 원문과 판정 범위

- 신규 기본 응답 상한은 30,000토큰입니다. 진단 호출마다 규칙 지시와 필요한 청구항 판본·문서 입력을 먼저 계산하고, 남은 공간과 모델 상한 내에서 출력 예산을 정합니다. 보고서에는 요청값과 호출별 적용 범위를 표시합니다. 기존에 저장된 상한은 설정에서 조정할 수 있습니다.
- 문서 전체가 들어가면 원문을 보내고, 한도를 넘으면 각 원문의 쪽별 관련 문구를 로컬에서 발췌합니다. 청구항 판본 전문은 유지합니다. 발췌로 검토한 규칙은 원문 인용을 대조하고, 생략 범위를 보고하며 전수 점검이나 발견 없음 판정은 보류합니다.
- AI 품질진단 시스템의 점검 항목을 기준으로 OA-01~17, RD-01~06, RC-01~07의 요약 규칙을 실행합니다. OA-15는 최후통지와 선행 통지, 당시 청구항 판본, 쟁점에 필요한 인용발명·명세서 등 원문을 대조합니다. 필요한 원문이나 검증 가능한 원문 인용이 빠지면 확인 불가로 표시합니다. OA-16·17은 통지 당시 청구항, RC-07은 검증된 등록청구항에 적용합니다.

- 행정처리 이력과 상품별 PDF 응답의 발송번호를 맞추고, 원문을 내려받아 페이지와 첫 쪽 식별자를 확인합니다. 경로 만료, PDF가 아닌 응답, 파일 손상, 텍스트 추출 실패, 식별자 불일치는 문서별로 표시합니다. 분석할 원문을 확인하지 못하면 외부 모델 호출 없이 진단을 보류합니다. 이미지로만 구성된 원문은 OCR이 필요합니다.
- 변동 이력을 접수번호·일자로 대조해 통지 전 청구항을 복원합니다. 같은 날의 선후가 불명확하거나 원문을 확보하지 못한 판정은 보류합니다. 등록청구항은 등록공보와 대조합니다. 확인된 등록 정정공보가 있는 경우 적용할 청구항 기준 시점의 검증이 필요합니다. 심결문과 경정결정문은 이력에서 식별된 심판번호와 서지를 확인한 경우에 조회합니다.
- 규칙별 LLM 결과는 원문에 존재하는 인용을 확인한 후 보조 판단으로 표시합니다. 공식 진단코드의 자동 확정과 외부 원문 없이는 판단할 수 없는 실체 결론은 보류합니다. 행정 이력, 청구항 변동, 인용문헌 식별정보를 개별 서류 PDF와 구분합니다. 이전 설치에서 확보한 PDF는 기존 로컬 자료로 열거나 다시 추출할 수 있습니다.
- 각 상품은 별도의 이용 권한이 필요할 수 있습니다. 원문을 외부 LLM으로 전송하기 전에 이용 조건과 전송 권한을 확인하세요. [KIPRIS PLUS 상품 목록](https://plus.kipris.or.kr/portal/data/apiClas/List.do) · [원문 이용 안내](https://plus.kipris.or.kr/portal/bbs/Faq_info.do?buttonIndex=&pageIndex=9)

## 개인정보와 검증

- 기본 설정은 웹 콘텐츠 인식과 기억 메모의 모델 전송을 끕니다. 일반 대화 전송 시 입력과 대화 맥락은 선택한 모델에 전송됩니다.
- KIPRIS PLUS 키는 LLM 키와 별도 로컬 저장소에 보관합니다. 일반 대화 내보내기에 키와 특허 진단 기록을 포함하지 않습니다.
- `npm ci && npm test`로 합성 자료 기반 테스트를 실행합니다. Chromium 통합 검증은 `npx playwright install chromium` 후 `DANGDANG_EXTENSION_DIR=dist/DangDang_internet npm run test:browser`로 실행합니다. 사용자의 실제 키나 문서는 테스트에 필요하지 않습니다.
